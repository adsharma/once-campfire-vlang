# once-campfire-vlang

Campfire in V, ported from `../once-campfire-go` (which ports the Rust Campfire).
Preserves the SQLite schema, storage layout, cookies, frontend, and behavior of
the Go app. See `REPORT.md` for the current porting status.

## Layout

Each `internal/<pkg>` of the Go port becomes a top-level V module here
(`rails`, `jobs`, `useragent`, `httpcompat`, `qrcode`, `zstd`, `database`,
`html`, `richtext`, `storage`, `integrations`). Tests live beside code as
`*_test.v`. Reference oracle vectors are vendored under
`integrations/testdata/` (pinned to the same reference commit as the Go port).

The application itself follows `../once-campfire-python` (`src/campfile`),
not the Go layout, so the python sources transpile to V one unit at a time:

| python (`src/campfile/…`) | V module | contents |
|---|---|---|
| `domain/campfire.py` | `campfire/` | pure domain rules over an in-memory `Store` |
| `domain/workload.py` | `workload/` | views, porter search index, seeder, hot paths |
| `config.py`, `state.py` | `campfile/` (`config.v`, `state.v`) | env config, per-request context |
| `db.py` | `campfile/` (`db.v`) | enum tables, time conversion, `load_store` |
| `fq.py` | `campfile/` (`fq.v`) | parameterized-SQL helpers (no ORM in V) |
| `queries.py` | `campfile/` (`queries.v`) | DB-backed reads + session auth |
| `ops.py` | `campfile/` (`ops.v`) | writes + admin operations |
| `routes/helpers.py` | `campfile/` (`http.v`) | `Req`/`Resp`, `present`/`error`, actor resolution |
| `routes/*.py` | `campfile/` (`routes_*.v`) | one file per blueprint, same paths |
| `__init__.py` | `campfile/` (`app.v`) | factory, seeding, routing, `net.http` glue |

The domain packages (`campfire/`, `workload/`) import nothing from
`campfile/`; all database and HTTP concerns live in `campfile/`. The
low-level SQLite engine is the existing `database/` module (shared Rails
schema, reader pool, single writer). Seed parity with python is asserted
byte-for-byte by `campfile/seed_vector_test.v` against
`campfile/testdata/seed_vector.txt` (generated by the python seeder).

## Intentional differences from the Go port

- **No TLS certificate/hostname verification on outbound fetches.** V's
  `net.openssl` binding never sets `VERIFY_PEER` and performs no hostname
  check, so link unfurls, webhook deliveries, and push sends skip verification
  (the Go port verifies against system roots). Scheme allow-listing, the SSRF
  IP guard, size caps, and redirect limits all still apply.
- **Outbound DNS is resolved twice per unfurl hop in production** (once for
  guard validation/pinning, once for dialing). Answers are pinned per hostname
  for the duration of one unfurl; the OS resolver cache makes the extra query
  cheap.
- **OpenGraph unfurl JSON emits keys in canonical order**
  (`title, url, image, description`) rather than document insertion order. The
  values are identical and JSON-object comparison is order-insensitive.
- **Oracle lookup/request accounting.** The reference `*_expected.json`
  oracles were recorded from the Rails app, whose resolution ordering differs
  from the Go port in dimensions Go's own suite never asserts (FTP probes
  resolve-then-reject in Rails vs scheme-reject in Go; redirect-chain lookup
  counts). Tests assert every recorded lookup host is guard-checked
  (set inclusion) and every recorded request occurs in order (subsequence), but
  not exact counts. Outcomes (status/body) match exactly on all 90 OpenGraph
  and 19 webhook cases.
- **`math.big` comparison pitfall.** V's `Integer.==` also compares internal
  digit-array lengths, so all P-256 field/point comparisons go through a
  value-based `big_eq` helper (`integrations/p256.v`).

## Intentional differences from the python port

- **Attributes on dataclasses.** Every `@dataclass` becomes a struct with
  attributes: `@[inline]` for the small value entities in `Store` slices,
  `@[direct_array_access]` where elements are rewritten in place, `@[heap]`
  for `Store`, `Rng` and `SearchIndex` (reference semantics like the python
  objects). V has no keyword construction, so `User(id=1, …)` becomes
  `User{id: 1, …}`; struct fields default to zero values, so only non-zero
  python defaults are repeated.
- **python `int` becomes `i64`.** V's `int` is pointer-sized and python ints
  are unbounded; IPv4 addresses alone need 33 bits, and the LCG multiply
  reaches ~2.4e18, so the whole domain uses `i64`.
- **Constants are `snake_case`.** V rejects uppercase identifiers, so
  `ROLE_ADMIN` → `role_admin`, mechanically.
- **`CHECKER.pre/post` contracts are dropped.** The py2many verifier
  annotations have no V equivalent; the `assert` statements stay, and V
  runs them in tests.
- **V has no exceptions, default arguments, or regex.** `Result` structs are
  kept as structs (not V sum types) for one-to-one parity; functions with
  python defaults take explicit arguments; the search-query sanitizer is a
  hand-written word-character loop.
- **`build_webhook_payload` takes one struct.** V has no call form that stays
  readable past four arguments, so the nine python parameters become a
  `WebhookPayload` struct.
- **Store operations are free functions, not methods.** `campfire.Store` and
  `database.DB` live in other modules and V forbids methods on non-local
  types, so `store.create_user(…)` becomes `s.create_user(…)` inside
  `campfire/` but `create_user(mut db, …)` in `campfile/` — exactly the
  python call shape (`c.create_user(store, …)`, `ops.create_user(db, …)`).
- **No query DSL.** `fq.py` (fquery.sqlmodel) has no V equivalent; `fq.v`
  is thin parameterized-SQL helpers, and every statement still uses `?`
  placeholders. `IN (...)` lists use bound placeholders, never
  interpolation.
- **Session cookies are HMAC-SHA256, not itsdangerous.** Like python's
  Flask-signed cookie (and unlike Rails), cookies are only readable by the
  server that wrote them; what travels between ports is the `sessions` row.
  Password digests stay interoperable: V's `crypto/bcrypt` writes the same
  format Rails and python store.
- **`message_mentions` is an extension table** (created by `campfile`), just
  like in python; the Rails schema and sibling ports ignore it.
- **No `room` SQL alias.** `room` misparses as an alias in SQLite, so table
  aliases are single letters (`m`, `r`, `u`) throughout `campfile/`.
